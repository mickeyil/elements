# Elements code review (2026-10-19, HEAD fac5e54)

Scope: the whole project (firmware `src/`, `compiler/`, `controller/elemctl/`, `controller/web_ui/`, build and
tools), about 31k lines of C++/Python/TS plus 25k lines of tests. Method: six Opus agents documented every file
and its intent as inferred from behavior (the existing docs had drifted); nine Opus agents then reviewed one concern
each, confirming bugs by running probes against the real decoder, engine, hub, session, web server and `sim_device`;
this doc is my synthesis plus my own reading of the engine, playback, session and compiler seams. The detailed
reports and probe scripts are kept under `local/review-2026-10-19/` (gitignored). Nothing else in the tree was modified.

Headline: the firmware core and device app are carefully built and mostly correct. The real problems sit at the
seams. Several large features exist in code but cannot be reached by any operator path, the controller can be
crashed by a routine Wi-Fi blip, and the compiler accepts programs the device rejects. About 4,800 lines are dead or
unreachable, and roughly another 3,000 can go through simpler shapes that the deep reviews prototyped.

---

## 1. The system in one page

```
DSL .py  ->  compiler (blob v5)  ->  controller (Python, one 50 Hz loop)  ->  devices (C++17: ESP32 | sim)  ->  LEDs
                                           ^  unix socket                         |  UDP frame previews (sim only)
                                      web.py relay  <-> browser (Vue)  <----------'
```

| Module | What it is | Key abstractions | Contract to its neighbors |
|---|---|---|---|
| `compiler/elements` | Turns a DSL module into one blob per strip | `StripDef`, `AnimDef.schedule` events, inferred layers, pool buffers, pixel views, copy ops, `CompiledManifest` | Blob v5 byte layout and the limits table, both mirrored by hand in `src/core` |
| `src/core` | Deterministic render pipeline, identical on ESP32 and host | `decode_program` -> `Program` -> `Engine` (boundary stepping: end, copy, start) -> `Compositor` -> `Strip` | Every frame is a pure function of program time; the engine never wraps, the player rewinds it |
| `src/controller` (device side) | The device app: discovery, TCP link, commands, playback state machine, clock sync, logs, flash animation store | `App`, `AppContext`, `ControllerLink`+`CommandProcessor`+`CommandHandler`, `Playback`, `ClockSyncClient`+`SyncedClock`, `AnimationStore` | Link protocol v7 (opcodes, ACK statuses, 11-byte status reply), three UDP side channels on fixed ports |
| `src/platform` | Interfaces plus ESP32 and sim implementations; `main.cpp` composes an `App` | `NetInterface`, `Tcp/UdpTransport`, `FileStore`, `KeyValueStore`, `FrameOutput`, `SystemPlatform`, `DeviceIdentity`, `now_us()` | Sim CLI flags, exit code 64, storage layout, frame packet, version string, all mirrored in Python |
| `controller/elemctl` | Session time, discovery server, device links, compile + distribute, panel takeover, OTA, status publishing | `DeviceHub` (sockets), `Session` (desired vs observed per `Member`, one command in flight), `ControllerService` (verbs + state dict), `ControllerServer` (unix socket) | Device wire (`wire.py`), client JSON protocol v3 (`controller_protocol.py`) |
| `controller/web_ui` + `web.py` | Relay (hand-rolled HTTP + WebSocket) and the Vue pages: Status, Panel, Viewer, Logs, Layout editor | `useServerState` (WS, snapshot, frames), pure `lib/*Model.ts`, `editorModel.ts` | Snapshot shape (web's fold of controller `state`+`catalog`), binary frames, REST routes |

Two facts that simplify a lot of what follows:

- **Exact replay.** `Engine::reset()` + `advance_to(t)` rebuilds the state at any time from boundaries alone (verified
  by the timeline review: dense, sparse and reset-then-render produce identical pixels on every sample program).
  So every time is a safe seek target, a START with the original anchor rejoins a show exactly, and the compiler's
  "safe intervals" protect nothing.
- **The controller is the authority, but three features let the device decide on its own**: the flash background
  playlist, the `DeviceMode` label, and controller-side "adoption" of whatever a device happens to play. The clean
  model is: the device reports `(playback state, blob crc, synced, skew)`; the controller decides everything else.

## 3. Findings

### 3.1 Decisions only the owner can make

These are features that exist in code and tests but cannot be reached by any operator path. Each needs a keep-or-cut
decision before the simplifications in section 4 can be sized.

**Status (2026-10-20).** The owner decided D1, D3, D4 and D6; the changes landed the same day (uncommitted when this
was written), each implemented and then reviewed by a separate Opus agent. The rest of this section is the review-time
snapshot of HEAD fac5e54 and was left as written.
- D1, option (a): wired. A program opts in with a module-level `SYNC = True` literal, parsed like `LOOP`; the default
  stays False and no file under `animations/` was changed. Untested on hardware. The review of the wiring found four
  things to expect on the first synced show; all four were fixed later the same day, one commit each: a playing or
  paused program now survives a detach whether synced or not (`App::shows_on_its_own_`), and a device that joins or
  reconnects under a synced program is STARTed on the shared anchor instead of parking; a synced START/RESUME is
  anchored 200 ms ahead (`_SYNCED_START_LEAD_US`) so every device begins together; sync `t2` is the kernel's arrival
  stamp (`SO_TIMESTAMPNS`, Linux-only); a refused command is logged once and a device waiting for clock sync is shown
  on its card. Left for later: a synced device that kept playing while the operator did stop/play or pause/resume
  during its drop stays on the old anchor until the next stop or load (the session could remember each member's
  confirmed anchor and STOP on mismatch); and bug 1 below is now reachable for a synced show that outlives a
  controller restart.
- D3: JUMP removed. Opcode 0x12 is retired, `PROTOCOL_VERSION` stays 7 (no wire bytes changed). Safe intervals,
  `required_start_ms`, the width filter and `memory_estimate.py` are gone with their tests.
- D4: no OTA password, by decision (trusted LAN). The password plumbing is deleted; the assumption is stated in
  `ota.py` and the README.
- D6: ports are `DEFAULT_PORT_BASE` (6040) plus fixed offsets in `link_protocol.h`, mirrored in `wire.py` and guarded
  by the regex parity test; the `controller.*_port` JSON fields are gone (an old key is rejected with a message);
  `--port-base` on `elemctl run/server/web/sim` and on `sim_device` moves the whole set. `test_hub_live.py` probes a
  free base, so the `/proc` test guard (`conftest.py`, `test_runtime_guard.py`) was deleted.
- D2 and D5 remain open.

**D1. Synced playback has never been reachable.** `service._compile` calls `build_manifest(beat, duration, loop)`;
`requires_sync` and `target_fps` keep their defaults, `program_metadata` reads only BEAT/DURATION/LOOP, and no file
under `animations/` could set them. Git history shows this was never wired. So every program the controller sends is
unsynced at 50 fps: devices anchor on their own receive time and START's anchor is ignored. Everything that exists
for sync (ClockSyncClient, SyncedClock, hub SyncServer, the Unsynced ACK and its backoff, the synced gating in
Playback, skew reporting) runs but changes nothing visible. The README's headline ("multiple devices play in
lockstep") is not true today.
- Option (a), recommended: wire it. A `SYNC = True` module constant read by `program_metadata`, passed through
  `_compile` to `build_manifest`, about 15 lines plus one test. Then validate on hardware the two things the link
  review flagged for synced shows: a Wi-Fi disassociation drops the link at once and the detach policy discards a
  synced program (suspected S-1), and the controller stamps sync `t2` when it *reads* the socket, not on arrival,
  roughly doubling device-pair error to ~5-7 ms p95 (S-3).
- Option (b): declare the project unsynced-only and delete ~1,200 production lines (and ~1,000 of tests).

**D2. The stored-background feature (flash playlist) has no caller.** `set_background` is a controller verb with no
UI, CLI, tool or doc reaching it; ERASE and QUERY_LOCAL are never sent. The firmware side is live (boot and detach
play entry 0), which is the source of bug 32 and of the second loop mechanism. The panel plus "unsynced survives
detach" (a9c0433) now covers what it was for. Recommended: delete it (about 2,300 lines: `animation_store`,
`local_animation`, `FileStore` and both implementations, five handlers, service `_bg_*`, wire codecs, four copies of
`FakeFileStore`, ~1,100 lines of tests). Keeping it means: a UI entry, loop-only blobs, an adoption policy, bug 32.

**D3. JUMP / seek.** The controller never sends JUMP; the compiler's safe intervals, `required_start_ms`, width filter
and memory estimate (about 260 production + 300 test lines) are read by nothing and are conceptually obsolete
(exact replay). Delete those regardless. Keep JUMP only if D1 is (a) and operator seek or live rejoin is wanted; then
drop its "strictly ahead of the cursor" rule, which assumed seeks could not rebuild state.

**D4. OTA has no password.** `ELEMENTS_OTA_PASSWORD` is defined nowhere, so any LAN host can flash any image over
UDP 3232 (the lamp also advertises over mDNS). On a trusted home LAN that is the same trust the link grants, raised
from "drive the LEDs" to "run code on a box holding the Wi-Fi passphrase". Accept and document, or put the define in
gitignored `secrets.h` and the same value in `controller.ota_password`; `ota.py` already does the auth.

**D5. Device label.** Stored, published, preserved on edit, never settable or shown from the UI. Show it on the card
(one line) or stop publishing it. Do not build an edit field.

**D6. Configurable ports.** `config.json` lets discovery, sync and log ports change, but the firmware and the sim
hardcode 6040/6043/6044, so changing them silently strands every device. Make them protocol constants (in
`link_protocol.h`, mirrored in `wire.py`) and drop the config fields. Carrying them in the OFFER cannot cover
discovery itself.

## 4. Simplifications and better abstractions

Ranked by payoff. Deltas are approximate production lines unless marked. Several were prototyped by the reviewers
(prototypes under `local/review-2026-10-19/deep/scratch-*/`).

**S1. Delete what no operator path reaches (about -4,800 lines, mostly after D1-D3).**
Stored background + `DeviceMode` + (if decided) JUMP in one protocol v8 bump (-2,300 incl. tests; needs an OTA of the
ESPs); after that `App::update_mode_` becomes "if detached and `requires_sync`, reset", ~8 lines instead of 60, and
`local_program_loaded` with its restart-on-Ended (the second loop mechanism) disappears. Safe intervals,
`required_start_ms`, width filter, `memory_estimate.py` (-560 incl. tests). `render.py` + `test_render.py` (-873),
`sim_helpers.py` + its test (-240, move `find_free_tcp_port`), `controller_helpers.py` (-97), `tools/esp32_smoke.py`
(-268), the `/proc` guard + `test_runtime_guard.py` (-170), writer verbs `publish/get_state/list_programs/shutdown`,
`extract_strips`, `member_*` events, `epoch`, web-invented snapshot counts (-150), `fonttools`/`brotli` requirements.

**S2. Compiler: one data-flow mechanism and strict per-animation encoders (compiler.py ~1050 -> ~650).**
- *Copy into the shift's own buffer.* Today a source is captured three ways (`self`, `direct`, `copy` into a
  "preserve" buffer, then `Shift::initialize` copies again into `work`). Prototype: one copy op at the source's end
  straight into the shift's work view, `src_idx = work_idx`; no blob or firmware change (the decoder already allows
  `src == work`). Identical pixels on six programs under dense and replay schedules, never more buffers (ring8: 11 ->
  10). Deletes `_plan_source_copies`, `_compute_required_starts`, preserve buffers and the three modes (-160). The
  contract becomes one sentence: "a shift captures its source's endpoint at the source's end into its own buffer".
  With it: require `source=` (bug 18), drop the layer-jargon errors (bug 17, -15), fix z-order (bug 5, +6) and
  document "overlapping events draw in declaration order, later on top". A small `PlannedEvent` dataclass then
  replaces the 14 private dict keys the passes annotate today.
- *Strict encoders.* One `_Params` reader where every read validates and raises `CompileError` (`num`, `time`, `rate`,
  `choice`, `flag`, `color`, `done()` for leftovers) plus one `_encode_<anim>` that reads, converts and packs in one
  place; `COLORS` become HSVA. Fixes bug 8 and all of bug 16 by construction, deletes `REQUIRED_PARAMS`, `TIME_PARAMS`,
  `_resolve_anim_params`, `_resolve_color`, `pack_params` and the resolve-dict/pack-dict seam (-120 net). A declarative
  schema table was considered and rejected: the five animations are too irregular and a table cannot reach C++.
- *Make the fixtures a real parity test.* One `BlobReader::read_finite_f32`, `r.done()` at the end of each
  `from_blob` (today extra param bytes decode Ok), a solid-paint event in a fixture. Reject empty pixel groups
  (treat `9-0` as descending or error).

**S3. Preview: per-sim latest picture plus a controller position event (-450, fixes bug 4).**
The bucket/dedupe/eviction assembler exists to align UDP packets from processes on one machine into atomic
multi-strip frames. The per-device path (`KIND_DEVICE_FRAME`) already exists for the panel. Make every sim frame
that sim's latest picture regardless of owner, coalesced per tick; the Viewer paints `deviceFrames` the way PanelPage
does; while PLAYING the controller emits a `position {cycle, t_ms}` event at ~4 Hz from its clock, which also gives
ESP-only shows a working readout. Deletes `preview.py` and its tests, ~60 session lines, `KIND_FRAME`, web `_apply_frame`,
TS `ingestFrame`/`latestSlices`. Behavior change: strips paint independently (invisible on localhost).

**S4. Web relay: one persistent asyncio connection, no roles (-190, fixes bugs 10-13).**
Replace the observer thread + queue + per-request writer `ControllerClient` with one `open_unix_connection` task that
routes replies by id (sketch in the client-plumbing report). Delete `controller_client.py`, the role split in
`server.py`, the hello spin. Command latency ~42 -> <=20 ms and nothing blocks the loop. Same change: SPA fallback (+3),
a backlog cap instead of the 0.1 s drain timeout (drop frames above 64 KiB backlog, drop the client above 4 MiB;
-20), a streak-deduped guard around `tick_once` (+7; the real fix is bug 1, but a live controller beats a dead one).
Keep the hand-rolled HTTP/WS server: aiohttp would save ~280 lines and add ~8 dependencies to a 3-entry
`requirements.txt`; its only defects are the two fixes above. State the 0.0.0.0 bind and the missing Origin check as
choices (an Origin check is 4 lines).

**S5. Device persistence: the profile is a length, and one less storage layer.**
Nothing ever writes a color order or gamma; FastLED's template argument already fixes the order. Make
`HardwareProfile` a `uint16_t`, drop `ColorOrder`, `copy_to`'s order/gamma parameters, `KeyValueStore::{get,put}_f32`
and the BGR/f32 tests (-150). Keep the SET_PROFILE reboot (live apply is possible but not simpler). Then: if D2 deletes
the background, the `FileStore` interface and both implementations go with it, and the sim's JSON KV store (the only
nlohmann user, 274 lines for one key) becomes a ~40-line text-file store; `test_wifi_cred_store` moves to an in-memory
fake (-250 and one dependency). If D2 keeps it, one stdio `FileStore` serves both platforms (LittleFS is a VFS at
`/littlefs`, `rename` is `::rename`) and the profile becomes a file in it (-700). Also: clock out only the profile's
pixels after one boot-time blank (`FastLED[0].setLeds(_leds, n)`; +3 lines, returns ~7.5 ms of every 20 ms frame on
the 50-px bench strip; lower `STRIP_MILLIAMPS` to ~2200 in the same change since the 250 phantom LEDs currently
reserve the ESP's share of the 2.5 A supply).

**S6. Build: CMake 1015 -> ~140 lines, every .cpp compiled once.**
One `elements` library of everything but `main()` and `now_us()`, a `test_clock` library, a `foreach` over
`test/test_*.cpp` (special cases: `test_pixel_buffer_pool_pooled`, `test_fixture_blobs`, the lamp), fixture
generators in a loop, drop the 200-line valgrind block (valgrind is not installed; `-fsanitize` is the cheaper
equivalent). PlatformIO filter 47 lines -> `+<core/> +<controller/> +<platform/wifi_cred_store.cpp> +<platform/esp32/>`,
`default_envs = esp32dev`, pin `espressif32` and `FastLED`. A `make test` that runs ctest, pytest and vitest. Take
`pio` out of `elemctl run`.

**S7. Layout: one geometry implementation, no hashes (-850 incl. tests, fixes bugs 6, 7, 25).**
TS stays the only expander (the editor needs instant previews). The server validates rows (range, duplicates,
canonical form) and stores `editor` as an opaque sidecar; the editor verifies the sidecar against the rows on load and
falls back to singles with a notice. Drop `csv_hash` and the never-enforced `base_csv_hash`. Derive `snapshot.layouts`
from the sim-device set (bug 27). In `editorModel.ts`: one per-type point table instead of seven switch blocks,
`serializeDocument` via `translatePrimitive`, derived `currentIndex`, no `cloneDocument` (-200). Then move handle
geometry and LED-list parsing into pure tested helpers and split the 1.8k-line page into ~6 composables.

**S8. Browser: a plain server-state store, rendering in the pages.**
`useServerState` keeps the parsed frame map and a `playhead`; ViewerPage computes its targets and paints with one
`watchPostEffect` exactly like PanelPage (-70 composable, +20 page; fixes bugs 13, 14, 33). `isStillLoading` honors
`blocked` and the card shows it (bug 9). Trim the contract to what the UI reads (snapshot counts, `member_*`,
`safe_intervals`, `epoch`, `session_id`, `pid`); show `uptime_ms` on Logs as `+12.3s` to match `server.log`. One
`ModalFrame` for the two modals (-100). Keep the snapshot fold: ~25 lines, and moving the offline rewrite into three
pages is churn.

**S9. Link and UDP side channels: collapse the code, not the channels (fixes bugs 15, 24, 29).**
Three UDP channels are justified (discovery precedes TCP; sync needs UDP timing; logs must work for a refused
device). What to collapse: `Registered` link state; `WireWriter/WireReader` plus a `write_slot` helper for DISCOVER,
PING, REGISTER and LOG instead of hand `memcpy` offset tables (-30); side channels take the live controller IP from
`ControllerLink` instead of reaching into `DiscoveryClient` (-10, App loses a constructor dependency); one UDP error
policy and optionally one shared `UdpTransport` (-12); `AckStatus` defined from `ACK_*`; a hub recv-loop helper
(-20); `hub.send` returns "queued". With D1: arrival-time `t2`. A single controller UDP port is worth doing only with
the v8 bump.

**S10. One pattern for every hand-mirrored constant.**
The repo already regex-reads C++ headers in `test_wire.py` and `test_blob_limits.py`. Extend that to `AnimType`,
`BLOB_VERSION`, the `AckStatus` enum, the three UDP ports (after D6 moves them into `link_protocol.h` and
`wire.py`), `SIM_REBOOT_EXIT_CODE` and the sim uid rule. Cheap, and it is the only cross-language guard the project
needs; generating code from a schema is not worth it at this size.

**S11. Session: keep the model, fix its two leaks (fixes bugs 1, 2, 19).**
The reconciler already is "desired vs observed, one next command"; a rewrite would move code around. Make the adopted
target honest: inject `adopt(strip_id, length, crc) -> (blob, token) | None` from the service (compile the panel
library once per (strip, crc)) and only adopt on a match, as the owner's decision states; otherwise leave the member
DETACHED, where Stop still works once STOP keys on observed phase. That removes the `('device', crc)` token kind,
`_panel_crc_ids`, the per-tick compile and `serving`. Delete `epoch`, `Member.cursor_us`, `Member.boot_token`, the
unused `rebooted`/`reason` arguments; `ProfileState` is a bool; make `edit_device` reset target/owner/profile on a
geometry change (S-4). The play-cohort guards look over-defensive but are not: the Unsynced backoff widens the race
window to seconds right after attach.

**S12. Platform: one Wi-Fi + OTA bring-up; `NetInterface` is `is_up()` (-110).**
A `WifiOta` used by both `esp32/main.cpp` and the lamp (merge creds, Wi-Fi step, OTA restart on link_up, handle while
up, optional password), with logging left to the composition root so the upward `controller/slog.h` include leaves
`platform/`. `App` stops calling `begin/poll` on the network. Delete the copy constructors the UDP transports claim to
delete; fix `merge_from` and the portal text.

**Explicitly left alone**, with the reviewers' reasons: the reconciler model; the hand-rolled HTTP/WS server; the
per-tick state rebuild-and-compare (microseconds, every alternative is more code); the decoder's temp-array copies
(KB-scale); `hsv_to_rgb` in Python (owner's decision); the snapshot fold; unbounded `ArtifactCache`, `pending` and
`ProtocolReader` (local trusted peer); sim detection by uid prefix (the prefix *is* the type contract); the Power-on
409 guard; three UDP channels; `App`'s ten constructor references (a struct wrapper is cosmetic).
